# مخططات تسلسل التفاعلات — نظام إدارة التدريب الميداني الجامعي

**الحالة:** مسودة للمراجعة مع صاحب المشروع.
**الصيغة:** Mermaid `sequenceDiagram`.
**المصادر المستخدمة:** `PRD.md` (المرجع الحاكم) ثم `docs/user-flow.md` و`docs/SRS` (FR-01..FR-07) و`docs/ERD.md` و`docs/diagrams/domain-model.md`.
**ملاحظة:** لا يوجد في هذه المسودة أي سلوك غير مذكور في المصادر. ما لم تحسمه المصادر مكتوب كـ «سؤال مفتوح» داخل المخطط أو في آخر الملف. أسماء حالات الطلب مطابقة لـ PRD §10.1.

**المشاركون المنطقيون في كل المخططات:**
- **التطبيق:** الواجهة والخادم معًا.
- **قاعدة البيانات:** مخزن البيانات (PostgreSQL حسب ERD).
- **الفواعل:** الطالب، المشرف الأكاديمي، مسؤول جهة التدريب، مسؤول الكلية، المسؤول الأعلى.

## 1. التسجيل الذاتي وتحقق البريد وتفعيل الحساب

**المصدر:** user-flow §1.1 و§2.1 و§3.1، وSRS-01 إلى SRS-04 وSRS-08.

```mermaid
sequenceDiagram
    actor U as المستخدم
    participant A as التطبيق
    participant D as قاعدة البيانات
    actor CA as مسؤول الكلية

    U->>A: اختيار الدور وإدخال بيانات التسجيل
    Note over U,A: الاسم الأول والأخير والبريد وكلمة المرور والكلية. للطالب أيضا الرقم الجامعي والتخصص. لمسؤول الجهة اسم الشركة
    A->>A: فحص الحقول الإلزامية وطول كلمة المرور 8 خانات على الأقل

    alt بيانات ناقصة أو كلمة مرور قصيرة أو كلية أو تخصص غير متاح
        A-->>U: منع الإرسال مع رسالة الخطأ المناسبة
    else البيانات صحيحة
        A->>D: إنشاء حساب غير مفعل مرتبط بالكلية
        D-->>A: تم الحفظ
        A-->>U: إرسال رسالة تحقق إلى البريد
        U->>A: فتح رابط التحقق

        alt تعذر الإرسال أو التحقق
            A-->>U: تعذر إرسال رسالة التحقق. حاول مرة أخرى.
        else تم التحقق من البريد
            A->>D: تسجيل تحقق البريد وإنشاء طلب تفعيل بانتظار القرار
            A-->>U: حسابك بانتظار موافقة مسؤول الكلية
            A-->>CA: وصول طلب تفعيل جديد
            CA->>A: مراجعة الطلب والتحقق من انتمائه لكليته

            alt موافقة
                A->>D: تفعيل الحساب وتسجيل من وافق
                A-->>U: الحساب مفعل
            else رفض
                A->>D: تسجيل قرار الرفض
                Note over A,D: وفق PRD §17 (قرار 21): الحساب مرفوض مع سبب؛ يجوز التصحيح وإعادة طلب التفعيل أو الاعتراض المسبب دون إنشاء حساب مكرر، مع حفظ سجل القرارات
            end
        end
    end
```

## 2. تسجيل الدخول وقفل المحاولات الفاشلة

**المصدر:** user-flow §1.1، وSRS-05.

```mermaid
sequenceDiagram
    actor U as المستخدم
    participant A as التطبيق
    participant D as قاعدة البيانات

    U->>A: إدخال البريد وكلمة المرور
    A->>D: قراءة الحساب وحالة القفل

    alt الدخول مقفل
        A-->>U: رفض الدخول مع عرض وقت أو مدة الانتظار
    else الحساب غير مفعل
        A-->>U: الحساب بانتظار موافقة مسؤول الكلية
    else بيانات الدخول خاطئة
        A->>D: احتساب محاولة فاشلة
        opt بلغت 5 محاولات فاشلة متتالية
            A->>D: قفل الدخول 15 دقيقة
            A-->>U: عرض وقت أو مدة الانتظار
        end
        A-->>U: فشل تسجيل الدخول
    else بيانات صحيحة وحساب مفعل
        A-->>U: قبول الدخول
    end

    Note over A,D: سؤال مفتوح: تصفير العداد وخطوات استعادة كلمة المرور غير موصوفة في المصادر
```

## 3. إضافة كلية وضبط المنطقة الزمنية

**المصدر:** user-flow §5.1، وSRS-06 وSRS-09.

```mermaid
sequenceDiagram
    actor SA as المسؤول الأعلى
    participant A as التطبيق
    participant D as قاعدة البيانات

    SA->>A: فتح إدارة الكليات وإدخال اسم الكلية والمنطقة الزمنية
    A->>A: التحقق من الدور ومن اكتمال الاسم والمنطقة الزمنية

    alt حقل ناقص
        A-->>SA: منع الحفظ وتحديد الحقل
    else منطقة زمنية غير صالحة
        A-->>SA: اختر منطقة زمنية صالحة.
    else البيانات صحيحة
        A->>D: إنشاء الكلية مع المنطقة الزمنية
        alt تعذر الحفظ
            A-->>SA: تعذر إنشاء الكلية. لم يتم تأكيد الحفظ. حاول مرة أخرى.
        else تم الحفظ
            D-->>A: تم الحفظ
            A-->>SA: تمت إضافة الكلية
            Note over A,D: وفق PRD §17 (قرار 18): الكلية غير مفعلة ولا تظهر في التسجيل حتى استكمال إعدادها وتفعيلها من المسؤول الأعلى
        end
    end
```

## 4. تقديم طلب التدريب ومراجعة جهة التدريب

**المصدر:** user-flow §1.2 و§1.3 و§3.3، وERD (سجل حالات الطلب).

```mermaid
sequenceDiagram
    actor S as الطالب
    participant A as التطبيق
    participant D as قاعدة البيانات
    actor PA as مسؤول جهة التدريب

    S->>A: فتح فرص التدريب
    A->>D: قراءة الفرص المفتوحة لكلية الطالب وتخصصه
    D-->>A: قائمة الفرص
    A-->>S: عرض الفرص

    S->>A: اختيار فرصة وكتابة رسالة اختيارية وإرفاق سيرة PDF اختيارية

    alt الملف ليس PDF
        A-->>S: ارفع السيرة الذاتية بصيغة PDF.
    else الملف صحيح أو لا يوجد ملف
        opt حفظ كمسودة
            S->>A: حفظ مسودة
            A->>D: حفظ الطلب بحالة مسودة
        end
        S->>A: إرسال الطلب
        A->>D: التحقق من أن الفرصة مفتوحة وأنه لا يوجد للطالب طلب نشط آخر

        alt الفرصة أغلقت أو امتلأت
            A-->>S: الفرصة لم تعد متاحة
        else للطالب طلب نشط قائم
            A-->>S: منع الطلب وعرض الحالة الحالية
        else الإرسال مسموح
            A->>D: حفظ الطلب بحالة قُدّم الطلب / بانتظار رد الشركة وتسجيل الانتقال في سجل الحالات
            A-->>S: تم إرسال الطلب
            A-->>PA: وصول طلب جديد للمراجعة
        end
    end

    PA->>A: فتح الطلب ومراجعة الرسالة والسيرة
    A->>D: إعادة قراءة الحالة الحالية قبل القرار

    alt قبول جهة التدريب
        A->>D: تحديث الحالة إلى موافقة الشركة / بانتظار اعتماد الكلية وتسجيل الانتقال
        Note over A,D: المقعد لا يحجز في هذه المرحلة
        A-->>S: إشعار بموافقة جهة التدريب
    else رفض جهة التدريب
        A->>D: تحديث الحالة إلى مرفوض من الشركة وتسجيل السبب والانتقال
        A-->>S: إشعار بالرفض مع السبب إن وجد
    end

    opt إلغاء الطالب لطلبه قبل الاعتماد النهائي
        S->>A: إلغاء الطلب النشط
        A->>D: تحديث الحالة إلى ملغى من الطالب وتسجيل الانتقال
        A-->>S: يمكنه التقديم على فرصة أخرى
    end
```

## 5. الاعتماد النهائي من الكلية وحجز المقعد وإنشاء التدريب

**المصدر:** user-flow §1.2 و§4.2، وERD (الطلب المعتمد ينشئ تدريبًا واحدًا).

```mermaid
sequenceDiagram
    actor CA as مسؤول الكلية
    participant A as التطبيق
    participant D as قاعدة البيانات
    actor S as الطالب

    CA->>A: مراجعة الطلب الذي وافقت عليه جهة التدريب
    A->>D: إعادة قراءة حالة الطلب والفرصة

    alt رفض الكلية
        A->>D: تحديث الحالة إلى مرفوض من الكلية وتسجيل السبب والانتقال
        A-->>S: إشعار بالرفض
    else اعتماد نهائي
        A->>D: بدء عملية واحدة غير قابلة للتجزئة
        A->>D: التحقق من وجود مقعد متبق وحجزه
        alt لا يوجد مقعد
            D-->>A: لا مقعد متاح
            A-->>CA: الفرصة لم تعد متاحة ولا يحجز مقعد ولا يعتمد الطلب
            Note over A,D: سؤال مفتوح: إعادة الفتح أو قائمة الانتظار غير محددة
        else المقعد متاح
            A->>D: حجز المقعد وتحديث الطلب إلى معتمد نهائيا
            A->>D: إنشاء سجل التدريب
            D-->>A: تم الحفظ
            A-->>S: إشعار بالاعتماد النهائي
            CA->>A: تعيين المشرف الأكاديمي
            A->>D: حفظ إسناد المشرف مع فترة التكليف
            Note over CA,D: سؤال مفتوح: سياسة الاعتماد عند عدم وجود مشرف متاح غير محسومة
        end
    end
```

## 6. تسجيل الحضور والانصراف واعتماد السجل

**المصدر:** user-flow §1.4 و§3.4 و§4.2، وERD (التاريخ المحلي بحسب منطقة الكلية).

```mermaid
sequenceDiagram
    actor S as الطالب
    participant A as التطبيق
    participant D as قاعدة البيانات
    actor PA as مسؤول جهة التدريب

    S->>A: ضغط تسجيل الحضور
    A->>S: طلب إذن الموقع أثناء الاستخدام فقط

    alt رفض الإذن
        A-->>S: شرح طريقة السماح بالإذن أو تقديم طلب استثناء
    else تم الإذن
        S-->>A: الموقع ودقة GPS لحظة التسجيل
        A->>D: قراءة الموقع المعتمد ونصف قطره
        A->>A: مقارنة موقع الطالب بنطاق الموقع وفحص دقة GPS

        alt موقع غير معتمد بعد أو خارج النطاق أو دقة GPS أسوأ من 100 متر
            A-->>S: لا اعتماد تلقائي. تقديم طلب استثناء (المخطط التالي)
        else الموقع مقبول
            alt لم يصل التسجيل للخادم
                A-->>S: لم يرسل التسجيل
            else وصل التسجيل
                A->>D: حفظ سجل الحضور بوقت UTC وتاريخ محلي بحسب منطقة الكلية
                A-->>S: بانتظار اعتماد مسؤول جهة التدريب
            end
        end
    end

    Note over S,D: تسجيل الانصراف في نهاية الدوام يمر بالفحص نفسه ويحدّث السجل ذاته

    PA->>A: مراجعة سجلات اليوم
    A->>D: قراءة السجلات بانتظار المراجعة
    alt اعتماد السجل
        alt الانصراف مسجل
            A->>D: حفظ الاعتماد وحساب الساعات = الانصراف ناقص الحضور بحد أقصى يومي حسب التخصص
        else لا يوجد انصراف
            A->>D: وسم السجل غير مكتمل دون احتساب ساعات
        end
    else رفض السجل
        A->>D: حفظ الرفض مع السبب عند الاقتضاء
    end
```

## 7. طلب تصحيح أو استثناء للحضور

**المصدر:** user-flow §1.5 و§3.4.

```mermaid
sequenceDiagram
    actor S as الطالب
    participant A as التطبيق
    participant D as قاعدة البيانات
    actor PA as مسؤول جهة التدريب

    S->>A: فتح سجل اليوم واختيار طلب تصحيح أو استثناء
    S->>A: إدخال التاريخ ونوع المشكلة والوقت المطلوب والسبب

    alt وقت أو سبب ناقص
        A-->>S: منع الإرسال وتحديد الحقل
    else لم يصل الطلب بسبب الاتصال
        A-->>S: لم يرسل طلب التصحيح. أعد المحاولة عند عودة الاتصال.
    else الطلب مكتمل
        A->>D: حفظ الطلب بحالة بانتظار مراجعة جهة التدريب
        A-->>PA: وصول طلب تصحيح جديد

        PA->>A: مراجعة الطلب
        alt اعتماد التصحيح
            A->>D: حفظ القرار وتحديث سجل الحضور
            A->>D: إعادة حساب الساعات بحسب الحد اليومي
            A-->>S: إشعار بالاعتماد
        else رفض التصحيح
            A->>D: حفظ القرار مع السبب إن توفر
            A-->>S: إشعار بالرفض ولا تحتسب الساعات على الوقت المطلوب
        end
    end
```

## 8. الاطلاع الاستثنائي على محادثة

**المصدر:** user-flow §4.4، وERD (سجل التدقيق).

```mermaid
sequenceDiagram
    actor CA as مسؤول الكلية
    participant A as التطبيق
    participant D as قاعدة البيانات

    CA->>A: طلب فتح محادثة تدريب
    A->>D: البحث عن بلاغ نزاع أو طلب رسمي قائم مرتبط بالتدريب

    alt لا يوجد بلاغ أو طلب قائم
        A-->>CA: لا يمكن الاطلاع على هذه المحادثة دون بلاغ نزاع أو طلب رسمي قائم.
    else المحادثة لا تطابق التدريب أو الكلية
        A-->>CA: منع الوصول
    else يوجد بلاغ أو طلب مطابق
        A-->>CA: طلب إدخال سبب الاطلاع
        CA->>A: إدخال السبب
        alt السبب فارغ
            A-->>CA: منع فتح الرسائل حتى إدخال السبب
        else السبب مدخل
            A->>D: تسجيل هوية المسؤول والوقت والسبب ومعرف المحادثة والتدريب
            alt فشل التسجيل
                A-->>CA: تعذر تسجيل عملية الاطلاع. لم يتم فتح المحادثة.
                Note over A,D: إجراء الفشل المغلق مقترح في user-flow وغير مذكور في PRD، وليس قرارا معتمدا
            else تم التسجيل
                A->>D: قراءة الرسائل
                A-->>CA: عرض المحادثة
                CA->>A: تسجيل القرار في البلاغ أو الطلب ذي الصلة
                A->>D: حفظ القرار
            end
        end
    end
```

## 9. مراجعة موقع تدريب جديد

**المصدر:** PRD §11.4 والبند 14 من قواعد العمل، وuser-flow §3.2 و§4.2.

```mermaid
sequenceDiagram
    actor PA as مسؤول جهة التدريب
    participant A as التطبيق
    participant D as قاعدة البيانات
    actor CA as مسؤول الكلية

    PA->>A: إضافة موقع جديد لفرصة
    A->>D: حفظ الموقع بحالة غير معتمد
    Note over A,D: الموقع غير متاح للتحقق من الحضور حتى المراجعة
    A-->>CA: وصول موقع جديد للمراجعة

    CA->>A: مراجعة بيانات الموقع وتحديد نصف القطر
    Note over CA,A: نصف القطر الافتراضي 150 مترا وقابل للتعديل لكل موقع

    alt موافقة
        A->>D: اعتماد الموقع وحفظ نصف القطر
        Note over A,D: يصبح الموقع مؤهلا للتحقق من حضور الطلاب
    else رفض
        A->>D: حفظ قرار الرفض
        Note over A,D: وفق PRD §17 (قرار 5): يلزم الاسم والعنوان وإحداثيات GPS ونصف القطر؛ التعديل يحتاج موافقة الكلية، والتعطيل لا يمحو السجلات السابقة. قواعد التكرار تفصيل تنفيذي
    end
```

## 10. التقييم النهائي وإغلاق التدريب

**المصدر:** PRD §11.5 والبنود 18 و19 و22 من قواعد العمل، وuser-flow §1.6 و§3.4 و§4.3.

```mermaid
sequenceDiagram
    actor PA as مسؤول جهة التدريب
    participant A as التطبيق
    participant D as قاعدة البيانات
    actor CA as مسؤول الكلية
    actor S as الطالب

    A-->>PA: اقتراب نهاية التدريب أو تأخر التقييم
    PA->>A: فتح نموذج التقييم النهائي
    PA->>A: اختيار تقدير وصفي لكل معيار من المعايير الستة
    Note over PA,A: ممتاز أو جيد جدا أو جيد أو يحتاج تحسين. والملاحظة العامة اختيارية
    PA->>A: إرسال التقييم

    alt معيار ناقص أو يحتاج تحسين بلا ملاحظة
        A-->>PA: منع الإرسال حتى استكمال الحقول
    else التقييم مكتمل
        A->>D: حفظ تقييم نهائي واحد وبنوده للتدريب
        A->>D: إغلاق التدريب مكتملا
        A-->>S: إتاحة التقييم للقراءة فقط
        A-->>CA: إتاحة التقييم
        A-->>PA: عرض ما أرسله وحالة استلامه فقط
    end

    opt تعذر تقديم التقييم
        CA->>A: تسجيل استثناء موثق وإغلاق التدريب دون تقييم
        A->>D: حفظ الاستثناء وإغلاق التدريب
        A-->>S: عرض أن التدريب أغلق دون تقييم نهائي دون كشف المداولات الداخلية
        Note over CA,D: وفق PRD §17 (قرار 10): مسؤول الكلية وحده يقرر الاستثناء بسبب موثق ومستند داعم مع التدقيق وإشعار الطالب والجهة، دون تقييم إيجابي تلقائي
    end
```

## الأسئلة المفتوحة التي ظهرت أثناء الرسم

1. حُسم رفض الحساب والاعتراض وإعادة طلب التفعيل وفق PRD §17 (قرار 21).
2. تصفير عداد محاولات الدخول وخطوات استعادة كلمة المرور (المخطط 2). غير مذكورة في PRD.
3. حُسم ظهور الكلية وحالة تفعيلها وفق PRD §17 (قرار 18).
4. ما يحدث لطلب قبلته جهة التدريب إذا امتلأت المقاعد قبل قرار الكلية (المخطط 5).
5. سياسة الاعتماد عند غياب مشرف متاح (المخطط 5، وفق user-flow). وسؤال PRD §17 رقم 8 عن إعادة تعيين المشرف لاحقا.
6. حُسم منع تداخل السجلات والسماح بغير المتداخلة وتصحيح السجل المعتمد بتدقيق وفق PRD §17 (قرار 3)؛ تبقى معالجة الأوقات غير المنطقية تفصيلًا تنفيذيًا.
7. حُسمت بيانات الموقع واعتماد التعديل وحفظ السجلات التاريخية وفق PRD §17 (قرار 5).
8. حُسم صاحب قرار استثناء التقييم ومتطلبات التوثيق والإشعار وفق PRD §17 (قرار 10).
9. الفشل المغلق عند تعذر سجل التدقيق (المخطط 8) مقترح في user-flow وليس معتمدا.

## مخططات لم تُرسم بعد

- ملاحظات المشرف وسجل تعديلها.
- طلب تغيير المشرف.
- الطلب الرسمي وإنهاء التدريب مبكرا (PRD §11.8).
- بلاغ النزاع.
